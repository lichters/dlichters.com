Brand guidelines and AI brand kit

Section 8.11 · 11 of 24 in this chapter · 11 min read

In short

  • A brand is much more than a logo. It is the colours, fonts and tone you use everywhere.
  • Keep one brand guidelines PDF with all the rules. Share it with every designer and helper.
  • Build brand-kit.json and voice.md before you write any email or product text.
  • Check automatic brand data against your real website. Ask the owner when something is missing.
This section has 8 parts. Tap one to open it.

Brand system and consistency

1 min
  • A brand is much more than a logo.
  • A full brand system is a set of rules for how everything looks and sounds. It includes:
    • a colour palette (the set of colours you use),
    • typography (the fonts, or letter styles, you use),
    • visual patterns,
    • textures (surface looks, such as grain),
    • and the same messages on every touchpoint (every place a customer meets your brand).
  • Consistency builds trust. It makes your business look professional and connected.
  • Keep colours, shapes, typography and layout the same on all brand visuals.
  • Customers then link each element to your brand over time.
  • A recognisable visual set looks more professional.
  • It is also easier to remember.
  • Keep the tone (the way the brand sounds), personality and visual identity the same across all ads.
  • Regular readers recognise and trust a stable identity.
  • Change only when a test shows a different approach is needed.
  • Once the logo is finished, build a branding deck (a slide set that defines colours, fonts, shapes and textures).
  • This keeps all future graphics and marketing material matching the logo.

Brand guidelines file: contents and export

2 min
  • A brand guidelines document is one PDF (a file that looks the same on every device) with all brand information.
  • It holds:
    • logo files in several formats and colours,
    • exact colour codes: hex (a colour code like #5f021f) and RGB (a colour written as red, green and blue numbers),
    • font names and pairing rules (which fonts go well together),
    • visual patterns and textures,
    • brand voice guidelines (how the brand speaks).
  • Share it with graphic designers, video editors, web developers and team members.
  • Then everyone builds consistent brand work.
  • A brand guidelines file should hold:
    • brand photography,
    • a moodboard (a collage of pictures that sets the mood),
    • tone and style notes,
    • brand use rules,
    • The project colour palette,
    • typography,
    • and a logo panel.
  • Keep the templates (ready-made layouts you fill in) in the same file.
  • Then every asset is built from the same source.
  • A guidelines file with colours, fonts, logo, photography and brand voice is a plug-and-play base (a ready base you add pieces to).
  • Once it exists, a new template or ad can be assembled in minutes.
  • The time goes into building the photography and voice first, not into each design.
  • Update the guidelines file whenever the brand changes: a new palette, font or voice.
  • Build every new template from the current rules.
  • Treat the file as a living document (a file that keeps changing), not a fixed one.
  • Logo rule: the company logo comes in three versions.
  • They can be used interchangeably and resized as needed.
  • The logo must never be altered.
  • Use only the official files from the shared brand folder.
  • keep the logo as a PDF in a shared files section.
  • Any team member can then send it to a vendor (supplier) or customer who asks for it.
  • Store it with the quote and invoice templates, so staff do not have to ask the owner each time.

Exporting the guidelines for the team and freelancers

  1. Open the completed brand guidelines document in Kittl (an online design tool).
  2. Click the Download button.
  3. Change the file format to PDF.
  4. Select the "Combine into one file" option.
  5. Download and share the PDF with all designers, video editors, developers and team members.

Textures and patterns

1 min

Creating textures and patterns for the brand guidelines

  1. Open your logo in Kittl.
  2. Duplicate it and move the copy to a new "Textures" artboard (a blank design page).
  3. Adjust the copy by changing opacity (how see-through it is), adding colors, creating gradients (smooth blends from one colour to another), or layering elements.
  4. Create 2-3 different texture variations.
  5. Include these in the brand guidelines document so designers can use them for backgrounds, borders and decorative elements across materials.

Brandfetch workflow

2 min
  • Brandfetch is a service that collects a brand's logo, colours and fonts from its website.
  • Get API access (a code that lets a program use the service) from the right page.
  • Do not click "Get started" on the brandfetch.com homepage.
  • Always click "Are you a developer? Get API keys".
  • This opens the developer dashboard (the control page for developers) and the MCP setup.
  • MCP (a plug that connects Claude to an outside tool) is set up there.
  • The brand context step runs one Brandfetch call on the brand's domain (its web address).
  • It pulls voice, colours and fonts.
  • The result is saved as brand-kit.json (a data file of labelled brand facts, written in JSON) and a separate voice file.
  • Every later skill (a saved task the AI runs) uses these files as input.
  • Do not skip the transformation stage (stage 3).
  • In this stage, the raw data (unsorted data straight from Brandfetch) is converted into a structured brand-kit.json and voice.md (a plain text file with simple formatting, called Markdown).
  • This step is critical to avoid generic AI outputs.
  • Converting raw Brandfetch responses (the data sent back) into structured JSON and Markdown files keeps later AI emails, copy and templates brand-specific.
  • They use the right colours, voice and positioning (where the brand stands against others), not generic ones.

Brandfetch run in one project

  1. Create a new folder in Claude Cowork (a Claude workspace) and set it as your working folder.
  2. Create a new project in Claude Cowork with a descriptive name (e.g., "email mastery course with AI").
  3. In the project chat, invoke the Brand Fetch MCP using a prompt like "Using the Brandfetch MCP, research www.example.com.au".
  4. Let the MCP fetch and display visual identity (logos, colors, fonts, social links) and brand context (tagline, mission, target audiences, voice attributes, style).
  5. Review the output for contradictions between longDescription (a long general description field) and actual product range, and note any data quality issues.
  6. In the same project, use a mapping prompt (an instruction that matches data fields to file fields) to transform both Brandfetch responses into brand kit.json and voice.md files using the field mappings provided.
  7. Save both files to your project folder.
  8. Optionally, visit the brand's website directly with Claude in Chrome (Claude working inside the Chrome web browser) to verify fonts, currency (the money type) and positioning details.

Field mapping for brand kit.json

A field mapping says which data item goes into which spot in the file.

Field in brand kit.json Source
brand.description get_brand_context.identity.description
brand.tagline get_brand_context.identity.tagline
brand.mission get_brand_context.identity.mission
brand.tags get_brand_context.identity.tags
positioning.value_proposition get_brand_context.positioning.value_proposition
positioning.target_audience get_brand_context.positioning.target_audience
positioning.products_and_services get_brand_context.positioning.products_and_services
visual.logos, colors, fonts get_brand.logos, colors, fonts
voice.summary, attributes, avoid get_brand_context.brand.voice.*
style.summary, attributes get_brand_context.brand.style.*
links.website, links.social your domain, get_brand.links
  • Use get_brand_context.identity.description (a data field name for the short brand description).
  • Do not use get_brand.longDescription.
  • longDescription is generic. It may contradict your actual product range and positioning.

Data quality checks

1 min
  • If Brandfetch returns an unclaimed profile (a brand page its owner has not taken over), that is normal for most brands.
  • Treat colours and fonts as scraped estimates (values collected automatically from the website).
  • They are not official brand standards.
  • Check the real fonts by visiting the site directly with Claude in a browser.
  • Using Brandfetch data as fully authoritative (fully trusted) when the profile is unclaimed leads to wrong colours, fonts and category descriptions.
  • Always cross-check with the actual website and live product listings.
  • Always check that the data matches your business, especially currency and product categories.
  • Example: Brandfetch returns USD pricing, but your domain is.com.au.
  • Check whether you actually sell in AUD, then correct the data.
  • Data quality score (a rating of how reliable the data is): the Silk The Label unclaimed profile scored 0.28.
  • That is relatively low.
  • It means colours and fonts were scraped, not verified by the brand owner.
  • Worked example, Silk The Label:
    • primary #5f021f (deep burgundy, a dark red-brown), the main colour,
    • accent #ffffff (white), the highlight colour,
    • Fonts: Helvetica (title), custom body font (set as a Shopify CSS variable, a named style setting in the store's code, so it cannot be read directly).
    • Logo available as PNG (a picture file with a see-through background, 820x96) and SVG (a sharp file that resizes without blur).
  • If Brandfetch returns incomplete data (a new or very small brand), ask the user directly.
  • Do not let Claude guess or invent brand information.
  • If Brandfetch cannot detect a field (for example, the heading font) or returns incomplete information, request the data from the user instead of generating a value.
  • Always verify colours, fonts and links with the user before finalising the JSON file.

Brand kit JSON and voice file

2 min

Prompt for the brand kit and voice file (verbatim)

Note: hexadecimal means a colour code such as #5f021f.

Develop your brand identity and communication style for email marketing through a structured workflow, saving all outputs to your brand folder. Begin by using Brandfetch to retrieve your website's branding data: logo, color values in hexadecimal format, typeface selections, and social media connections. If Brandfetch returns limited information-which is typical for recently launched businesses-ask directly for the details rather than assuming. Never guess at brand attributes or rely on outdated cache; always verify by asking when uncertain. Create a JSON file called brand-kit.json in the brand folder using this exact structure: a brand object containing name, domain, tagline, and description; a positioning object with value proposition; a visual object with logos, three hex colors (primary, secondary, accent), and font details split by type (title, body); a meta object listing the URL and social platform accounts such as Facebook and Instagram; an industries field; and a location object with city and country. Verify the extracted colors directly against your live website, paying special attention to the primary hex code that styles your primary buttons, and confirm that both fonts and all shop and social links are current. Remove any inaccuracies. Determine your brand voice by asking how your organization should be perceived (options ranging from friendly to formal, or playful to premium), collecting 2-3 email or product description samples you consider successful, then drafting voice.md in the brand folder that documents a concise voice statement, 4-6 defining voice characteristics, representative language patterns your team uses, and a brief list of communication practices to avoid.
  • Worked example, Silk the Label (www.silkthelabel.com.au): Brandfetch returned the logo, primary colour #5f021f (deep burgundy), location (Brisbane, Australia), and Instagram and Facebook links.
  • The user confirmed the hex code matched their main button colour and gave 2-3 email examples.
  • Claude then drafted voice.md with tone attributes (traits of the tone) matching those examples.
  • Both output files are mandatory before the next part of the work begins.
  • Email and product descriptions cannot be on-brand without both files.
  • File naming varies:
    • "brand-kit.json" is the name used in the template.
    • "brandkit.json" appears in the mandatory-files rule.
    • "brand kit.json" appears in the transformation rule and mapping table.
  • Use brand-kit.json, as named in the template.

voice.md contents

voice.md is the brand voice file: a plain text file that describes how the brand speaks.

Element Description Source
Voice summary One-line statement of how the brand sounds (e.g., "Playful, premium, eco-focused") User input
Voice attributes 4-6 defining traits (friendly/formal, authoritative/approachable, minimal/warm) From 2-3 brand email or product examples
Language we use Specific words, phrases, tone patterns, punctuation style Extracted from provided examples
Never do this Guardrails: tone and language to avoid (e.g., "never use slang", "never make unverified claims") User guidance + example analysis
  • Converting the mapped data into a brand kit and voice file keeps the brand's voice, colours and positioning in everything written from it.

Keeping work inside one project

1 min
  • Keep all brand kit work inside one Claude Project (a saved Claude workspace with its own files and memory).
  • This includes the prompt, Brandfetch data, JSON, and voice file revisions.
  • This keeps the model's full context.
  • Splitting work across separate chats breaks context continuity (the link between what was said before) and can trigger hallucination (when an AI makes up facts).

Applying guidelines to templates and assets

2 min
  • Keep every template in the brand palette.
  • Pick each colour from the document's brand colours, not the template defaults.
  • Apply the same colour system across all formats.
  • Social, email and web assets then look like one brand.
  • Brand guidelines are a guide, not a rulebook.
  • Small deviations from the palette are acceptable when they improve fit.
  • For example, shift a pink accent toward a purple already in the brand.
  • Check that the change still reads as the brand.
  • The brand's main colour must appear in every rebranded layout.
  • Keep that colour consistent across the batch.
  • If the brand uses a different colour from the reference, ask Claude to rewrite the instruction so it uses your colour.
  • A logo or brand name on a generated ad is optional.
  • Leaving it off gives more room for the product message.
  • Remove any brand line that repeats the headline or crowds the layout.

Setting up email template branding in Shopify Email

Shopify Email is the email tool built into the Shopify store platform.

  1. Open the Shopify Email settings and scroll to the template branding section at the bottom.
  2. Click Customize.
  3. Upload the store logo in the logo field.
  4. Enter the store name in the store name field.
  5. Choose the same font used in the Shopify theme settings (the store's design settings) in the typography field.
  6. Set the colours to match the theme settings: the text colour, the button and link colour, and the colour for labels and outlines.
  7. Save all settings.
  • Email template branding should match the store's website: same logo, colours and fonts.
  • Once it is set in the template branding, all future email automations (emails sent automatically on a trigger) and campaigns use it by default.
  • So it only needs to be configured once.

Reference style set (Source A, a different brand, as an example of the format)

  • Brand fonts: body text (the main reading text) and tagline (the short slogan) use Gotham Book. The free alternative is Montserrat Light.
  • The website font is Proxima Nova. The logo font is Jenna Sue.
  • Brand colours: logo Red #e91e47 and logo Yellow #f7e100.
  • Body text is dark grey #484341 instead of black.
  • Buttons and links use Light Blue #17dbe1.
  • The wordmark (the brand name written as the logo) is True Black #000000.
