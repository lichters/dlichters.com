Playbook › 4. Store build and Shopify

Speed, apps and technical health

Section 4.17 · 17 of 20 in this chapter · 35 min read

In short

  • Your store is fast when its theme (the design template), apps and images are light.
  • Aim for a First Contentful Paint (the time until the first content shows) under 3 seconds.
  • Test speed with GTmetrix (a free speed-test site) and read its waterfall (a chart of what loads last).
  • Remove apps you do not need, because each one adds code.
  • Compress images before upload, which means making the files smaller.
More key points
  • Every picture needs an image alt tag, a short written description of it.
  • Videos can slow your store. Only embed a video (show it inside your page) when it helps people buy. Otherwise, link to it.
  • Use as few apps as possible. Each app adds code, which slows the store.
  • Removing an app can leave its code behind. Ask the app's developer to remove it, then check the speed again.
  • Do not change a product's URL handle (the name part of its web address) after the store is live. Changing it breaks links and search rankings.

Theme choice and code weight

3 min
  • On Shopify, code weight decides speed. Code weight means how much code a page must load. It depends on the theme, apps (add-on tools) and images, not on Shopify's own servers. Light themes load faster than heavy themes with messy code.
  • The installed theme has the biggest effect on page speed, so choose a theme built for fast loading. Manhattan is described as a fast-loading option.
  • Page speed is an SEO (search engine optimisation, getting found on Google) ranking factor. It also affects conversion (the share of visitors who buy). Choose a lightweight theme with minimal code, and limit installed apps, because each one adds code weight.
  • Store speed is an SEO ranking factor, so fix slow pages as part of search work.
  • Choose a theme with clean, lightweight code. Compare candidate themes' speed before committing, because speed-optimised themes are not all equal.
  • For fast collection pages (pages listing several products), use an optimised theme such as Manhattan, and install as few apps as possible. Image compression helps, but the theme and the number of apps have the bigger effect.
  • Free Shopify themes such as Sense and Refresh generally load quickly. They are a good base when speed matters.
  • Page builders such as PageFly are drag-and-drop tools for designing pages. They add a layer on top of the theme and increase load time somewhat. Weigh that cost against the conversion features they provide.
  • Theme updates can shift load time by as much as 10 seconds. Test whether the theme itself causes slowness. If it does, change the theme or invest in improving it.
  • Custom code in the theme keeps a site faster than stacking extra apps. A developer (a person who writes code) can add a feature such as sorting when the theme lacks it. Paid apps remain an option when custom development is not affordable.
  • Responsiveness (how well the page adapts to screen size) directly affects the mobile conversion rate. Use a theme from the Shopify Theme Store (Shopify's official theme shop) or a trusted developer, and design with mobile users first.
  • Improve speed with quick code changes rather than an expensive hosting upgrade. Hosting is renting server space. A costly host for a small speed gain reduces net profit (what is left after all costs) and can lower the sale price.
  • Do not hire Fiverr freelancers (people offering services on an online marketplace) to boost site speed unless you understand their method. They often inject code (add hidden code) that hides the site from speed-testing tools. This can be penalised or banned by Google.
  • The legitimate ways to reduce load time are compressing images and removing apps that are not needed.
  • Keep JavaScript (a programming language that makes pages react) and theme libraries (ready-made code packs) to an absolute minimum. Use only open-source libraries (code anyone can read and reuse) under the MIT license (a free-reuse licence). Avoid bloated libraries, because many premium themes (paid themes) load a large number of them.
  • Use CSS (style code) for simple animations instead of JavaScript, for example with the Animate.css library. This keeps the page lighter.
  • Use system fonts (fonts already on the visitor's device) where possible. They load much faster than custom web fonts (fonts downloaded with the page). Font loading is one of the biggest factors in store speed.
  • Heavy visual effects such as full-screen video backgrounds, parallax effects (backgrounds that move as you scroll) and many moving elements slow page loading. Avoid them unless they clearly help sales.
  • Keep the number of product variants (versions of one product, such as size or colour) reasonable. Too many variants can slow a store. Review the speed impact with GTmetrix rather than relying only on the Shopify speed score.

Theme and admin settings

1 min
  • In the early stage, leave the Advanced, Custom styles and scripts, and Performance settings at the Shopify defaults. The default performance settings are already set correctly for the theme.
  • To change robots.txt (the file that tells Google which pages to read) or other theme files, go to the theme editor and open the code editor. Shopify support documentation covers the exact process.
  • Turn off quick view (a popup preview) on collection pages. Its code loads before the customer clicks, it slows the page, and there was no evidence it increased conversion. Customers can open the product page instead.
  • Avoid sliders (image sets that rotate by themselves). Check whether a carousel (another name for a slider) is really needed at shouldiuseacarousel.com.
  • Remove quick shop functionality (a fast-buy feature).
  • Keep homepage slideshows and large hero images (big banners at the top) only if analytics (visitor statistics) show visitors click them and buy. If they are not clicked, remove them. They add load time without helping the sale.
  • Shopify shows an online store speed score only when password protection is disabled. The score can take 1 to 3 days to calculate after that. It shows as unavailable while the store is password protected.
  • Your store's speed score depends on which apps are installed, whether the theme's code has been modified, and how large the images and videos are.

Measuring speed

9 min

Which tool to trust

  • Use GTmetrix (a free speed-test site) for page speed readings. The Shopify admin score gives a less accurate picture of how fast a store loads.
  • Shopify's Speed Score is not a reliable indicator of performance. Use GTmetrix to analyse (examine in detail) load speed.
  • The Shopify admin speed score drops after any app or script (a small piece of code) is added, even on a fast theme. The GTmetrix waterfall (a chart of each item's loading order) shows what actually loads slowly for visitors.
  • Measure speed on Google PageSpeed Insights (Google's free speed test) and GTmetrix rather than the Shopify speed score. Use fewer apps rather than more, because the speed score is unreliable for judging real performance.
  • The key page speed metric is First Contentful Paint (FCP), the time until the first content appears. It should be under 3 seconds. Check it in Google PageSpeed Insights or GTmetrix by pasting the product page URL (web address).
  • The Shopify online store speed score combines many factors and matters less than First Contentful Paint. In the author's experience, removing unused JavaScript with a developer had little effect. Removing apps and image optimisation (making images smaller and lighter) had the most impact.
  • The speed-score numbers in Shopify's Online Store speed report are overall factors and do not matter much. The most impactful steps were image optimisation and removing unused apps. A developer can remove unused JavaScript for a fee.
  • Shopify's speed score can show as low even when pages load in under two seconds. Test with several speed tools and look at real load times rather than optimising for the score alone.
  • Shopify's own analytics script can show up as very slow in speed tools, sometimes around 30 seconds. It loads in the background and does not hurt the customer experience. Check whether it is the real cause before removing anything.
  • GTmetrix provides a free waterfall report for any URL. It shows what loads slowest and which elements cause problems. No paid plan is needed.
  • GTmetrix measures page load speed and performance scores for a store URL. Use it to check product and landing pages (the pages ads send people to) for speed problems before sending paid traffic to them.

Which page version and conditions to test

  • Mobile and desktop share the same Shopify admin changes. Optimisations made in the admin apply to both devices without separate mobile work.
  • Test store speed on both desktop (computer) and mobile separately. A store can load fast on one and slower on the other. Only treat a problem as real if it appears in the test results, not in a single personal impression.
  • Check product page load time on mobile.
  • Test under worst-case conditions, such as a slow 3G mobile connection (an older, slow mobile network), not only on home Wi-Fi or good LTE. Check that the site loads fast enough and stays usable in that scenario.
  • Test the final canonical URL (the main official address of the page). If PageSpeed Insights reports that the requested URL was redirected (sent on to another address), for example from http to https (from the unsecured to the secure address) or from non-www to www, every visit pays for that extra redirect step.
  • Test your store regularly with Google PageSpeed Insights, GTmetrix or Pingdom (another speed-test site).
  • Re-run the test after a few minutes, since cached results (saved older results) can change the score. (older: 2023 is not old; see note below)

Core metrics and what they mean

  • LCP stands for Largest Contentful Paint, the time until the biggest visible item on a page loads. It measures how long that largest element takes to load. Check it in GTmetrix on mobile and desktop, and fix the element that loads slowest.
  • Layout stability (how still the page stays while loading) is part of page speed scoring. Elements that move while the rest of the page loads are a sign that the theme code needs a developer review.
  • To check layout shift (CLS, Cumulative Layout Shift, how much things jump around), reload the page and watch for elements that jump after the initial load. Typical causes are upsell widgets (small boxes that suggest extra products), financing widgets (instalment-payment boxes) or other apps that inject (add) content late. Removing those apps usually removes the shift.
  • The standard PageSpeed Insights Opportunities list gives suggestions with estimated savings in seconds. The Diagnostics list gives extra detail that does not directly change the Performance score. Start with the red items, typically removing unused JavaScript, deferring offscreen images (loading images later, when visitors scroll to them), sizing images properly and removing render-blocking resources (files that hold back the page from showing).
  • PageSpeed Insights diagnostics can flag text that stays hidden while web fonts load. This does not change the Performance score. It signals that the font loading setup should be checked.

Targets and benchmarks

  • Aim for an average page load time under 5 seconds. Observed conversion differences between roughly 3 and 5 seconds were negligible, while a difference between 10 and 5 seconds clearly affected conversion.
  • Page load time should stay well under 10 seconds. Pages taking longer than about 10 seconds cause visitors to leave before the page fully loads. This hurts conversion and retention (keeping visitors coming back).
  • Most items on a page load within about three seconds. If a page takes around 10 seconds on mobile, find the one slow element with a waterfall test rather than removing everything.
  • Only the first product image, title and price need to appear within the first seconds on a product page. Sections lower down may load late without hurting the customer's first impression.

  • GTmetrix benchmarks judged very good for a Shopify store: performance score 97, structure score 87, Largest Contentful Paint 671 ms (milliseconds, thousandths of a second), Total Blocking Time 140 ms (how long the page is stuck and cannot respond), and Cumulative Layout Shift 0.02.   • In one case, two embedded videos (videos placed on a product page) dragged the GTmetrix grade down to E, with a 48% performance score. Removing them raised the grade to C. Well-built stores typically reach an A with around 99%.
  • A speed score around 38 may be acceptable if the cause is minor. Look at what is causing the slowdown before deciding whether the score matters.
  • Older stores with heavy code can sit at D+ and still sell well. New stores typically reach B or A.
  • Benchmark a store's performance score against the largest e-commerce sites (the biggest online shops). Run the biggest e-commerce brands through a tool such as GTmetrix and compare their scores with your own. If your store scores as well as or better than them, treat the score as acceptable. Do not delay launch to raise it further. (older: undated, see note below)
  • Fix slow pages on your own store before comparing it with a slow-loading competitor. A slow competitor is a weakness you can exploit, but your own store must not have the same problem.
  • Revenue impact of load time (how long a page takes to show):
    • 79% of customers who are dissatisfied with web performance are less likely to buy.
    • For a store earning $100k per day, a one-second speed improvement adds about $7k in daily revenue. This shows why load time is a direct revenue question.
    • A one-second delay in load time typically causes an 11% loss in page views and an overall 7% loss in conversions.
    • The common claim that each second of load time cuts conversion by about 10% is unreliable. Test your own store. Bringing a site down to a 1 to 2 second load time can require developer time, so it is only worth it when the benefit is measurable.

Test procedures

GTmetrix waterfall: find the cause of a slow site

  1. Go to gtmetrix.com and enter your store URL.
  2. Create a free account if asked to see the results.
  3. Open the Waterfall view.
  4. Look at the items loading last, on the right side of the list. Large videos or a single slow app are common causes. (2023)

GTmetrix: create a free account and read the waterfall

  1. Enter the store URL in gtmetrix.com.
  2. Create a free account, which needs no credit card.
  3. Run the test and read the scores.
  4. Open the Waterfall section, where the bars show what loads from fastest to slowest.
  5. Identify the slowest element, such as an image, video or app, and decide whether to remove or replace it.

GTmetrix: test and fix (grade target)

  1. Run the store URL through gtmetrix.com.
  2. Aim for an A or A+ grade.
  3. Open the waterfall and look at the slowest items at the bottom of the list.
  4. Remove or optimise the items that take the longest, such as large videos, oversized images, unused apps or tracking scripts (code that follows visitors).
  5. Recheck the grade after each change.

GTmetrix: test and fix (short version)

  1. Enter the store URL and click test.
  2. Open the waterfall to see the load order.
  3. Note the items that take longest, such as apps, large uncompressed images (images not yet shrunk), videos or broken code.
  4. Remove unneeded apps, compress images and repair broken code.

GTmetrix: test and read the waterfall

  1. Enter the store URL with HTTPS and run the test.
  2. Open the waterfall view and scroll down. The items loading longest appear furthest to the right, in milliseconds.
  3. Optimise those items, for example by compressing images, or remove code from apps no longer used.

Test and fix page speed with GTmetrix (with script check)

  1. Open gtmetrix.com and run a test on the store URL.
  2. Read the report for the elements slowing the page, such as videos, large images or apps.
  3. Before removing an app, search the page source (the page's hidden code; press Cmd+F on Mac or Ctrl+F on Windows) for the app or developer name.
  4. Remove or replace the heavy element.
  5. Re-run the test after a few minutes, since cached results can change the score. (2023)

Test with GTmetrix and fix in order

  1. Run the store through GTmetrix.
  2. Open the waterfall view and look at how each element loads.
  3. Identify the slowest elements at the bottom of the waterfall.
  4. Check the likely culprits: embedded videos, oversized images and apps that add extra code.
  5. Fix them yourself or outsource the fix.

Find the source of a slow item on a product page

  1. Open the waterfall report for the slow page.
  2. Find the item at the bottom of the list, which loads last and takes the longest.
  3. Copy that item's code or URL.
  4. Search for that code on Google to find its source. See whether others have fixed the same slowdown, for example in the Shopify community forum or in developer documentation. (2024)

Improve product page speed

  1. Test the page on GTmetrix.
  2. Read the waterfall, which shows each element and how long it takes to load.
  3. Identify the one or two slow items, such as an app, a large image or a video.
  4. Remove or modify those items.
  5. Compress all images so they load fast.

Find what slows a store with GTmetrix (waterfall, product-level check)

  • Use the procedure above for the waterfall and the Opportunities list. The waterfall shows which items load last. Those are the first candidates for optimisation, usually apps, oversized media or broken code.

Order of work for speed

2 min

Improve store speed in this order

  1. Avoid sliders. Check whether a carousel is really needed at shouldiuseacarousel.com.
  2. Remove quick shop functionality.
  3. Optimise images: use the proper file format, crop (trim) and scale (resize) them to the display size, and compress them with TinyPNG or Crush.Pics (free online image shrinkers).
  4. Keep only essential apps.
  5. Update your theme.
  6. Optimise and minify your code (remove extra spaces and comments so files are smaller).

Improve page speed in this order

  1. Test the site regularly with Google PageSpeed Insights, GTmetrix or Pingdom.
  2. Check whether the theme causes slowness. If so, change the theme or invest in improving it, because theme updates can shift load time by as much as 10 seconds.
  3. Reduce front-end apps, meaning apps that run JavaScript as the page loads. Replace simple app features with custom code from a developer where practical.
  4. Compress images before uploading them, using an offsite tool such as ImageOptim rather than in-store compression apps, which are unreliable.
  5. Embed videos from YouTube or Vimeo in a lightweight way, instead of with the standard Shopify embed code, which is often the largest element in page load time.
  6. Hire a developer with Shopify page speed experience if fixes are too technical, for example through onlinejobs.ph, freeup.net or toptool.com.

Improve page speed (image and app focus)

  1. Use GTmetrix or Google PageSpeed to identify the main issue, usually images or GIFs (short animated pictures).
  2. Compress images below 300 KB (kilobytes, a small file-size unit) and GIFs below 800 KB (ideally under 1 MB).
  3. Target product images under 50 KB while keeping the quality nearly the same, using TinyPNG or Photoshop.
  4. Install as few apps as possible, since each app adds JavaScript that runs on every page load. Remove unused apps and their code.
  5. Note that page builders such as PageFly add an extra layer on top of the theme and slow the page. Weigh the speed cost against the conversion features.

Speed check and fix

  1. Run the store through GTmetrix or Google PageSpeed.
  2. Identify the main issue, which is usually large images or GIFs.
  3. Compress the images and GIFs with TinyPNG or Photoshop.
  4. Remove apps that are no longer used, together with their code.
  5. Re-test the page speed.

Images

2 min

Compression and format

  • Compress product images to small file sizes to reduce product page load time. This improves both search engine rankings and user experience.
  • Compress all images so they stay high quality on screen but have small file sizes.
  • Compress all product images before uploading them, for example with TinyPNG. Use lower resolution (fewer pixels) so pages load within a few seconds. Slow-loading product images cause visitors to bounce (leave straight away).
  • Shopify has begun serving the WebP image format (a small-size picture format) automatically to supporting browsers such as Chrome. This speeds up loading without any action from the store owner. Continue using Shopify's built-in handling and focus your own optimisation on other areas.
  • Convert all JPEG, PNG and GIF images to WebP. A 1 to 2 MB (megabytes) JPEG can drop to about 200 KB or less. Use an online converter for bulk conversion (converting many files at once) instead of an image app.
  • Speed up animated GIFs by converting each GIF to WebP. GIFs of 1.5 to 5 MB typically drop to about 200 to 500 KB as WebP.
  • Compress oversized supplier images before uploading them, for example files around 20 MB, because heavy media slows the store.
  • Oversized image files force the browser to shrink them, which slows page loading. This matters once the store goes live, even if it does not matter for a demo site used to call suppliers. Shrink them before the store goes live.
  • Speed tools often flag oversized images on mobile. A 1000 by 1000 pixel image that looks fine on desktop can be too large on a small screen. Serve a smaller image to mobile devices to fix this warning.
  • A reliable approach for device-specific images is to load a separate desktop version and a separate mobile version. Switch between them with media queries (rules that pick content by screen size). Responsive srcset attributes (code that offers several image sizes) were described as not always reliable.
  • Lazy loading (loading images only when a visitor scrolls near them) is a code feature. Shopify's Turbo theme and some other themes have it built in. Other themes need a developer to add lazy loading code or a theme change. The author knew of no reliable app for this.
  • Crop and scale images to the display size before upload, and use the proper file format.

Image alt text (SEO and accessibility)

1 min
  • SEO means search engine optimisation. It is how you help Google find and rank your pages.
  • Accessibility means making the store usable for everyone.
  • Every image on the site needs an image alt tag. This is a short written description of a picture.
  • In Shopify (the platform that runs your online store), you can add it easily in the image settings.
  • Image alt tags must be descriptive.
  • Include at least one keyword (a word people type into search) that fits the content of the page where the image appears.

Video and embeds

2 min
  • An embed means showing a video inside your page with a code snippet (a small piece of code). It is not the same as uploading the file.
  • Embedded YouTube videos do not slow site loading. (older: 2020; see "Where sources disagree" below)
  • The reason given: embedded videos are served from YouTube's servers (YouTube's computers).
  • Do not upload the video directly to Shopify.
  • Do not embed it like a YouTube or Vimeo player. This slows the site.
  • Instead, host the video through LyveCom, a video hosting service.
  • Hosting through LyveCom keeps load times lower. Load time means how long a page takes to open.
  • LyveCom also gives you e-commerce analytics (reports on how shoppers use the store).
  • Embedded videos on product pages load slower.
  • They also lower your page speed score (a number that rates how fast a page loads).
  • They do not hurt the shopper's experience.
  • Embed a video only when it helps conversion. Conversion means a visitor buys.
  • Otherwise, upload it to a YouTube channel (your YouTube account for videos).
  • Link that channel from the product description.
  • Link your social profiles in the store footer (the bottom part of every page).
  • The standard Shopify YouTube embed loads a large JavaScript file. JavaScript is code that makes a page do things.
  • It does this even when the video is not playing.
  • This adds seconds to load time.
  • Use a thin embed. This is a light embed that loads the JavaScript only after the visitor clicks play.
  • Do this through custom code (code written for your store), which is preferred, or through a light app.
  • Standard YouTube or Vimeo embeds are often the biggest part of a page's load time.
  • Embed them with a lightweight method instead. Lightweight means it uses less code.
  • This matters most on product pages that use video.
  • Common speed problems include large page videos.
  • Other common problems: oversized images (files bigger than the page needs), unused app code, and tracking scripts (small programs that record visitor activity) from Google or Microsoft.
  • Background tracking scripts often add load time. Visitors often do not notice.
  • Do not embed large PDFs directly in product pages. A PDF is a document file, such as a manual.
  • Upload the file to Shopify Files (Shopify's file storage area) or Dropbox (an online file storage service).
  • Link to it with a text link or a PDF icon image.
  • A new Shopify store loads very quickly at first.
  • Slowdowns come from many videos.
  • They also come from uncompressed high-resolution images. Uncompressed means not made smaller in file size. High-resolution means very detailed and large.
  • Apps also cause slowdowns.
  • Check speed after each batch of content or app changes. A batch is a group of changes made at once.

  • Ask the app developer which code to delete after uninstalling.

Reduce app code that slows the store

1 min
  1. Remove apps you do not use.
  2. Message each app developer in the Shopify app store to remove the code they injected. Removing an app does not always remove its code.
  3. Measure speed on Google PageSpeed Insights (Google's speed-testing tool) and GTmetrix. Do not rely on the Shopify speed score.

Find leftover app code in the page source

1 min

Page source is the hidden code behind a web page.

  1. Open a store page in Google Chrome (a web browser) and choose View page source. (2023)
  2. Search the page for the uninstalled app's name. Press Cmd+F on Mac, or Ctrl+F on PC. (2023)
  3. Check the matches (the results the search found).
    • Leftover code from the app shows up as matches. (2023)
    • Some remaining matches may belong to apps still in use. (2023)
  4. Check the store's URL (its web address) on BuiltWith, a website that lists the tools and software a site uses. (2023)
  5. Email the app developer through the Shopify app store. (2023)
  6. Ask them to confirm the app is fully removed. (2023)
  7. Ask whether any remaining code must be removed manually. (2023)
  • BuiltWith shows the tools and software installed on a website. (2023)
  • Enter its URL to see them. (2023)
  • This can help confirm that unwanted apps are no longer present. (2023)

Custom code instead of apps

1 min
  • Custom code in the theme keeps a site faster than stacking extra apps. Stacking means adding many apps on top of each other.
  • Replace simple app features with custom code from a developer where practical.

Scripts, fonts and mistakes in code

1 min
  • Mistake: heavy session-recording apps add load time.
  • Tracking scripts also add load time.
  • Check each one against its speed cost.
  • When copy-pasting code (copying it and pasting it elsewhere), word processors (text programs such as Microsoft Word) can convert straight quotes (plain quote marks) to curly quotes (fancy quote marks).
  • That change breaks the code.
  • Copy the code from the original source and follow its instructions exactly.
  • Do not change tracking or theme code without checking its load time afterwards.

JavaScript errors

1 min
  • JavaScript errors can break add-to-cart (the button that puts an item in the shopping basket). (2025-26 source)
  • They can ruin the customer experience even when the ads and product are fine. (2025-26 source)
  • Check the add-to-cart flow after every theme or app change. A flow means the steps a shopper takes. (2025-26 source)
  • Leftover code from several freelancers and removed apps can create many JavaScript errors.
  • These errors stop other scripts from running.
  • So cart upsells can fail silently.
  • A performance fix (a change made to speed things up) can break a page.
  • One store lost sales after it added a speed optimisation app.
  • The cause was script placement (where the script sits on the page).
  • That placement kept the main product images from loading quickly.
  • This lowered conversion.
  • Check the product page visually after any speed change.
  • A mandatory terms-and-conditions checkbox (a box shoppers must tick to agree to the store's rules) added to the cart with a third-party app (an app made by an outside company) can add about 0.5 seconds to cart load time.
  • Replacing it with a small HTML addition in the theme avoids that delay.

Cookie consent

1 min
  • Cookie consent is a pop-up at the bottom of the page where visitors accept cookie tracking.
  • It is a separate section at the bottom of the theme editor sidebar (the left-side menu in the theme editor), below Footer.
  • Turn cookie consent on for stores selling into the EU (the European Union, a group of European countries).
  • Cookie opt-in (the visitor says yes) is required there.
  • Leave it off if it is not needed.
  • Cookie consent banners (pop-ups) are mainly needed because of EU laws. (2023)
  • Ask support how to add one to an older theme. Support is Shopify's help team. (2023)
  • Do not build it yourself. (2023)

Accessibility

1 min
  • Analyse colour contrast (the difference between text colour and background colour) and component sizes (the size of buttons and other parts).
  • Use accessibility apps where they add extra support.

URLs and handles

1 min

Product URL pattern

1 min
  • A URL is a web address. A URL slug is the readable end part of it that names the page.
  • Create product page URLs in this format, with keywords in the slug.
[Brand Name]-[Product Name]-[SKU#]
  • The SKU# is a stock code, a unique number for each product.
  • This makes the URL more descriptive for SEO.
  • Use this pattern:
brand-name-product-name-sku
  • Use dashes, not underscores (the _ symbol). (2023)
  • Example:
herman-miller-aeron-chair-9876
  • This matches what competitor stores (other stores selling similar products) do. (2023)
  • It helps Google understand products. (2023)
  • In Shopify, the domain (your store's main address) and the path prefix (the folder part, such as /products/ or /collections/) are created automatically.
  • The only part you edit is the slug that follows them.

Handles: set once, change carefully

1 min
  • A product's URL handle should be set once. (2023)
  • Keep it unchanged after the store is live. Live means open to customers. (2023)
  • Changing it breaks existing links and rankings (where you appear in search results). (2023)
  • A product title can be changed freely. (2023)
  • Changing names and descriptions without changing URLs is safe. (2023)
  • Do not change product URLs without setting up redirects. A redirect is a rule that sends an old web address to a new one. (2023)
  • If a product URL handle is changed after the page has ranked (appeared in search results) or received links (links from other websites), create a redirect from the old URL to the new one. (2023)
  • Redirects are needed only for pages that already have traffic (visitors), rankings or external links. (2023)
  • When you change a product's URL handle in Shopify, a checkbox called 'Create redirect' appears. (2023)
  • Keep it selected for any product that already has rankings, backlinks (links from other sites), or ad traffic (visitors from paid ads). (2023)
  • Unchecking it leaves the old URL broken. (2023)

Change product URLs on a live store

1 min
  1. Set up redirects from the old URLs to the new ones. (2023)
  2. Check in Google Search Console that there are no issues. (2023)
  3. Resubmit the sitemap (a list of your pages that you give to Google) to Google Merchant Center as soon as possible. (2023)
  4. Consider pausing ad campaigns during the change. This stops the old link from leading to a dead page (a page that does not work). (2023)

Change product titles and handles before launch (order of work)

1 min
  1. Make all product title and URL handle changes before submitting the sitemap or feed (your product list sent to Google). (2023)
  2. Delete the sitemap submitted in Google Search Console. (2023)
  3. Delete the product feed in Merchant Center. (2023)
  4. Make the changes you want. (2023)
  5. Resubmit the sitemap and re-add the product feed after the changes are finished. (2023)
  6. Create redirects only for pages that already had traffic or links. This is not needed before the store has launched. (2023)

Hiding products

1 min
  • Hiding a product from the Online Store sales channel (the place you sell online) removes it from the homepage and collections (groups of products).
  • It keeps the product itself.
  • Google then sees a broken link and 404 errors (a "page not found" message) for that URL.

Find pages returning 404 errors in Google Analytics

1 min

Google Analytics is Google's visitor-tracking tool.

  1. Go to Behavior.
  2. Open Site Content.
  3. Click All Pages.
  4. Find the row for the 404 page and click it.
  5. Add the secondary dimension (an extra column of detail) Source to see which source sends traffic to that page. Source means where visitors came from.
  6. Medium or Term can be added for more detail. Medium means the type of traffic. Term means the search words used.

Redirects

1 min
  • A 301 redirect is a permanent forward from an old web address to a new one.
  • Use redirects only where absolutely needed.
  • Each redirect adds an extra loading step.
  • 301 redirects can be created by hand in the Navigation section (Online Store > Navigation).
  • You do not need an app for this.
  • For redirecting many old URLs at once, a bulk redirect app (an app that handles many at once) can be installed.
  • 301 redirects are set in the Shopify admin under the navigation settings.
  • An app can be used to manage many redirects in bulk.

Redirect for a renamed collection

1 min
  1. Rename the collection in Shopify if it is necessary. (2023)
  2. Add a URL redirect from the old collection address to the new one in Shopify. (2023)
  3. Confirm the old URL forwards to the new page. (2023)

Hosting and technical limits

1 min
  • Hosting means the servers that keep your site online. Shopify is a hosted platform, so it runs those servers for you.
  • Technical SEO means the behind-the-scenes search settings of a site. On Shopify, it is limited to the settings and features the platform shows the store owner.
  • Advanced server-level changes (changes to the computer that runs the site) are outside the scope of a Shopify store owner.
  • Platforms such as WordPress with WooCommerce or Magento (other store-building systems) give the owner more control over hosting and server features than Shopify does.
  • These self-hosted platforms (where you run your own hosting) can carry out technical SEO measures that a Shopify store cannot.

Canonical and SEO basics

1 min

Canonical

1 min
  • The canonical code (a code line that tells Google which page is the main version) goes into theme.liquid (the main page file of the theme).
  • Put it inside the head section (the hidden top part of a page's code), directly before the closing head tag (the marker that ends that top part).
  • Paste it exactly as provided, with no edits.
  • The code itself is not in this text. Get it from the source it came from.

Meta descriptions and Yoast

1 min
  • Every page on the website needs a unique meta description. This is the short summary text shown under a page's title in search results.
  • Pages without one, such as those that fall back to the menu text, produce weak snippets (short preview text in search results).
  • Do not use Yoast SEO on Shopify. Yoast SEO is a search-settings add-on made for WordPress sites. (2025)
  • It is not recommended for Shopify stores. (2025)

Keeping pages out of Google

1 min
  • To keep a page out of Google, remove it from the sitemap so it is not submitted.
  • Or add a noindex tag (a code line that tells Google not to list a page) via the back end (the admin area behind your store).
  • Pages that already receive clicks, such as a warranty page, are usually better left indexed. Indexed means listed in Google.
  • Use a noindex tag on duplicate test pages (copies of pages used for testing).
  • This stops search engines from treating them as duplicate content (copies that compete with each other).
  • Apply it through a noindex app on Shopify.
  • The duplicate page is marked noindex through a noindex app available for Shopify.
  • A page that shows up too often in on-site search results (results from the search box on your store) needs a theme-level fix (a change to the theme's code).
  • This fix is not built into the theme.
  • Email support with the exact question.
  • Let developers check it.

Indexed pages in Search Console

1 min
  • In Google Search Console, a Shopify store showing around 128 indexed pages and around 2.52K non-indexed pages is normal. (2024)
  • Non-indexed means not listed in Google. (2024)
  • Most non-indexed URLs are duplicates created by product variants (versions of a product, such as different sizes or colours). (2024)
  • Check whether the non-indexed pages are normal:
    1. Count the pages on the store (products, blogs, other pages). (2024)
    2. Compare that count with the number of indexed pages. (2024)
    3. If they roughly match, the other URLs are variant duplicates that Google should not index. (2024)

Speed and ranking

1 min
  • Store speed is a ranking factor for SEO. A ranking factor is something Google uses to decide where you appear.
  • Page speed is a critical SEO ranking factor.

Forms and spam protection

1 min
  • Spam protection is a tool that blocks fake form submissions.
  • In Online Store > Preferences > Spam protection, enable Google reCAPTCHA on contact forms. reCAPTCHA is a test that proves a visitor is a real person.
  • Optionally, also enable it on the login, create account and password recovery pages.
  • Some customers may then be asked to complete a reCAPTCHA task.

Where sources disagree

3 min

These sources do not always agree. Use the rules below.

  • YouTube embeds: one 2020 source says they do not slow a site.
  • Its reason: they are served from YouTube's servers.
  • Later sources say embeds slow the page.
  • Embedded videos load slower on product pages.
  • The standard Shopify embed loads large JavaScript even when not playing.
  • Use the thin or lightweight embed when a video is needed.
  • Embed only when it helps conversion.
  • How much the score matters: several sources say the Shopify admin score (the speed number in your control panel) is unreliable.
  • Better tools are GTmetrix or Google tools.
  • One source says the score matters less than First Contentful Paint (how long until the first content appears on screen).
  • Another says its overall factors do not matter much.
  • The score depends on apps, theme code and media size (how big the pictures and videos are).
  • Use the waterfall (a chart showing each file loading in order) and First Contentful Paint as the main signals.
  • Grade targets: one source says aim for an A or A+ during a fix.
  • Another says A is preferred, B or B+ is fine, and older heavy stores can sit at D+ and still sell.
  • Aim for A while fixing.
  • Accept B when the store already sells.
  • App count: one source gives a typical count of 4 to 5 apps for a new theme.
  • Another says no fixed number of apps slows a store, and one poorly coded app is enough to matter.
  • Use the blueprint list as the limit.
  • Judge each app by its code.
  • Revenue per second: one source gives an 11% loss in page views per second.
  • It also gives 7% in conversions per second.
  • Another says the 10% claim is unreliable.
  • It advises testing your own store.
  • Test your own store before budgeting for speed work.
  • WebP: Shopify serves WebP (a modern, smaller picture format) automatically to supporting browsers.
  • The advice is to keep using that.
  • Another source says to convert all JPEG, PNG and GIF images to WebP before upload.
  • The sources do not explain how the two fit together.
  • Use Shopify's built-in handling for delivery (its automatic way of sending pictures).
  • Convert GIFs and oversized files before upload.
  • Image compression tools: sources name TinyPNG, Crush.Pics, Photoshop and ImageOptim.
  • One older source says in-store compression apps (apps inside the store that shrink images) are unreliable.
  • It recommends an offsite tool (a tool used outside the store).
  • Use an offsite tool.
  • Sliders and carousels: one source says avoid sliders (picture boxes that change on their own).
  • Another says keep a slideshow only if analytics (store statistics) show clicks and sales.
  • Remove them unless you can measure clicks and sales.
  • Redirects: one older source says use redirects only where absolutely needed.
  • Another says redirect whenever a live product URL changes. (2023)
  • A third says redirects are needed only for pages with traffic, rankings or links, and not before launch.
  • Redirect pages that already have traffic, rankings or links.
  • Mobile versus desktop: one source says admin changes apply to both devices.
  • Another says test each device separately, because a store can load fast on one and slower on the other.
  • Make the change once in the admin.
  • Then test both devices.
  • Cached results: one source says cached results (saved copies that load faster) can change the score.
  • So re-run the test after a few minutes.
  • Another says Shopify caches content heavily, so a theme change can take a while to appear live.
  • Wait for the cache to update before judging a change.
