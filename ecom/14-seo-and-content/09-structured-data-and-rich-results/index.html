Structured data and rich results

Section 14.9 · 9 of 20 in this chapter · 8 min read

This section has 10 parts. Tap one to open it.

Why structured data matters for CTR

1 min
  • Structured data, schema markup and rich snippets all refer to the same thing: code added to a website that gives search engines extra data about the business, products and stock, which search results can display.
  • Schema markup can pull review ratings, product price and stock status into search results, and search engines show this data alongside the normal listing.
  • Structured data is installed separately from the meta title and description.
  • Product listings can show star ratings from reviews, the product price and the category. These details make a listing stand out and can raise click-through rate.
  • Structured data passes store information to Google in the format Google expects, so product listings can show more details. Shown details can include the product title, URL, star ratings, price and stock status.
  • Structured data helps a result look more trustworthy and informative, which tends to lift CTR.
  • Rich results raise CTR, which signals to Google that the page should rank higher.
  • CTR from search results is a relevance signal for Google, so more clicks on a listing with strong reviews can also support organic rankings. Review markup is one way to make a listing stand out.
  • A result with rich snippets draws more attention and clicks than competing results without markup, so it can indirectly help rankings.
  • Add rich snippets, meaning Schema.org structured data markup, to product pages so that price, availability and ratings appear directly in search results, which increases click-through rate.
  • Use rich snippet data (reviews, price and stock) in search results.
  • CTR improves most when the URL, the title, the meta description and the structured data work together. JSON-LD lets organic listings and blog posts show rich snippets, which can raise CTR on pages and blog posts.
  • The more business information you enter in the Organization schema, such as email, description, address, social profiles and logo, the more Google can pass along to search results. Complete entries help raise CTR.

Ranking effect: sources disagree

1 min

What the rich snippet looks like

1 min
  • A product search result can show a star rating with review count, the price and an "In stock" status. The stars come from Review schema, the price and stock status from Product schema. The review data may come from a review app, while the markup code is separate.
  • Review schema displays yellow star ratings that stand out strongly from the rest of a search listing and attract the eye. This only helps when the product's rating is good.
  • Product schema lets Google show price, stock status, review stars, delivery and return information for product pages in organic results. Smart SEO includes schema, and judge.me adds review stars.
  • The handling days, transit days, return policy and shipping details entered in structured data should match what is shown on the store's own pages. Different values can create inconsistent information for Google.

Schema types to enable

1 min
Type Use Condition Ids
Website Enable as the first step of the setup Always
Organization Enable with business name, URL, contact and logo Always
Product Main type for product pages, enabled after Organization Always for product pages
Review Star ratings in results (yellow stars) Only when the product has good ratings
Local business Location data Only when the business has a physical local presence. Online-only stores keep it off
Collection Lets Google recognise the page as a collection Turn on after Product schema
Breadcrumbs Navigation path in results Turn on after Product schema
Article Blog posts Turn on after Product schema
FAQ Questions and answers in results Only once the store has a growing set of questions and answers, for example from a Q&A app. Not needed at launch
Recipe and How-to Recipe and instructional content Keep off unless the store publishes that kind of content
  • Only enable structured data types that match real content on the store.
  • For most e-commerce stores, Review schema and Product schema are the main types. Local business schema is mainly relevant to businesses with a physical location, and only some of their pages need it.

Choosing the implementation: app or theme code

1 min
  • Some Shopify themes include schema markup in the Liquid code for product pages. Check the theme for existing markup before adding anything, to avoid duplicating or conflicting with it.
  • Most Shopify themes have rich snippet data on by default. Verify that it is turned on.
  • JSON-LD structured data is added to a Shopify store with an app, not by theme code alone. The app originally recommended for it was rebranded in 2023. Stores that already use JSON-LD can keep it in place.
  • Writing schema markup by hand and keeping it updated is a recurring burden, because schema formats change and outdated markup stops showing in search results. Most store owners who are not coders would need to pay a developer for every update.
  • On Shopify, the recommended way to implement schema markup is a dedicated schema app, not a manual developer job. The app's developers update the markup automatically, so the store owner does not need to request updates.
  • Even if a Shopify theme already includes some structured data, install a schema app. Theme developers often do not maintain that markup, so a managed app is more reliable. Schema apps cost money, but the course presents them as a worthwhile investment.

Smart SEO setup

1 min

Enable JSON-LD in Smart SEO and check each part:

  1. Go to Apps > Smart SEO > JSON-LD.
  2. Check that structured data is valid for blogs and articles and covers every place where rich snippets are needed.
  3. In the Collections setting, tick the Collections checkbox so the collection structured data is added. [L368.018]

Follow this procedure for the Pro plan:

  1. Open the JSON-LD section of the app.
  2. Turn on Website schema.
  3. Turn on Organization schema.
  4. Enter the business name written as words, not as a domain. For example, enter the brand name, not a.com address.
  5. Enter the store URL.
  6. Fill in email, description, address and social profiles. These fields are optional but should be filled out as completely as possible.
  7. Upload the store logo.
  8. Click Save.
  9. Keep Local business turned off for a non-local online store.
  10. Turn on Product schema.
  11. Click Configure and link your Judge.me product reviews. This requires Judge.me installed on the store.
  12. Click Save.

Then turn on the additional types:

  1. Turn on Collection schema.
  2. Turn on Breadcrumbs.
  3. Turn on Article schema for the blog.

Case: after one setup in Smart SEO, the store has its logo, social URLs, price range, phone number display and Judge.me review connection. Product listings can then show the star rating, price and category directly in Google results, which makes them more attractive than competitor listings.

Reviews in rich results

1 min
  • In Judge.me, the review widget title can be set to load with the product title through a setting in the app's settings area. In Stamp.io, this requires adding a small piece of code to the site, which the vendor provides.
  • A review widget title containing the product name, for example "product reviews", can help the product page rank for searches for that product's reviews. This only works when the product actually has reviews to show.
  • Reviews from supplier websites can be used even if they are 2 to 3 years old. Hiding review dates is not a known policy violation. [L964.135]
  • In Google Search Console under Review snippets, all product pages with reviews should be valid (green). Invalid review snippets usually mean a code problem on the site. When reviews come from an app such as Judge.me, valid snippets allow review stars to show with product pages in search results.

Testing and verification

1 min
  • Google's free Structured Data Testing Tool checks whether Google can read the structured data on a given page URL. It is the reliable way to verify schema installation, instead of judging by search results.
  • Procedure to check a page:
    1. Open Google's free Structured Data Testing Tool.
    2. Enter the URL of the page you want to check.
    3. Read whether Google reports that it can see structured data on that page.
    4. If Google detects the structured data, the implementation is working, even if the rich snippet does not show in search results.
    5. If Google does not detect it, the schema is not installed correctly and needs to be fixed.
  • The Structured Data Testing Tool named in the lesson has been replaced by newer Google tools, such as the Rich Results Test. Before following the steps above, confirm the current tool Google offers for checking structured data in 2026.
  • After a JSON-LD app is installed, resubmit and recrawl the sitemap. If Search Console still shows few snippets after that, contact the app's own support, who can check the settings.

Limits and common mistakes

1 min
  • Google does not always show structured data in search results, even when it is installed correctly. Results can differ by query and by searcher. Searching your own product and not seeing the rich snippet does not prove that the schema is broken.
  • Only turn on Local business for product schema if the business has a physical local presence. Online-only stores keep it off.
  • Recipe and How-to schema should stay off unless the store publishes that kind of content.
  • FAQ schema is not needed at launch. Turn it on only when the store has a growing set of questions and answers.

More rules worth knowing

1 min

  • Smart SEO app > JSON-LD > Enable structured data: make sure the Collections checkbox is ticked. This adds collection structured data so Google can recognise the page as a collection.

  • Use the reviews from supplier websites, even if they are 2 to 3 years old. Hiding review dates is not a known policy violation.
